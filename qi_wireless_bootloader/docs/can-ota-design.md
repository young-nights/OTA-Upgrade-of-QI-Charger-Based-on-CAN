# CAN-OTA 无线升级技术设计文档

**项目**: QI 无线充电模块 CAN-OTA 升级方案  
**芯片**: AT32F426KBU7-4 (Cortex-M4F, 180MHz, 128KB Flash, 20KB SRAM)  
**版本**: v1.0  
**日期**: 2026-07-28

---

## 1. Flash 布局

```
+---------------------------+ 0x08000000
|                           |
|     Bootloader (16KB)     |
|     0x08000000-0x08003FFF |
|                           |
+---------------------------+ 0x08004000
|                           |
|     APP_A (48KB)          |
|     主应用区               |
|     0x08004000-0x0800FFFF |
|                           |
+---------------------------+ 0x08010000
|                           |
|     APP_B (48KB)          |
|     备份区 (v1不使用)       |
|     0x08010000-0x0801BFFF |
|                           |
+---------------------------+ 0x0801C000
|                           |
|     OTA 标志位 (16KB)      |
|     0x0801C000-0x0801FFFF |
|                           |
+---------------------------+ 0x08020000
```

### 1.1 各区域说明

| 区域       | 起始地址     | 大小    | 用途                           |
|------------|-------------|---------|-------------------------------|
| Bootloader | 0x08000000  | 16KB    | 启动引导、OTA 升级逻辑、CAN 通信 |
| APP_A      | 0x08004000  | 48KB    | 主应用程序                      |
| APP_B      | 0x08010000  | 48KB    | 备份区（v1 不使用，预留）         |
| OTA 标志位  | 0x0801C000  | 16KB    | OTA 请求标志、升级状态           |

### 1.2 OTA 标志位定义

| 地址         | 值           | 含义                 |
|-------------|-------------|---------------------|
| 0x0801C000  | 0xFFFFFFFF  | 无 OTA 请求（擦除态）  |
| 0x0801C000  | 0x544F4152  | OTA 升级请求 ("RAOT") |
| 0x0801C000  | 0x544F4144  | OTA 升级完成 ("DAOT") |

## 2. CAN-OTA 帧格式定义

### 2.1 CAN ID 分配

| CAN ID  | 方向             | 用途       |
|---------|-----------------|-----------|
| 0x100   | 主机 → 设备       | 命令帧     |
| 0x101   | 主机 → 设备       | 数据帧     |
| 0x102   | 设备 → 主机       | 应答帧     |

### 2.2 命令帧格式 (CAN ID = 0x100)

```
字节    内容            说明
[0]     命令码          OTA_CMD_xxx
[1-4]   参数            命令相关参数（小端序）
[5-7]   保留            0x00
```

| 命令码 | 值     | 参数含义                     |
|--------|--------|----------------------------|
| START  | 0x01   | [1-4] = 固件总大小 (uint32)  |
| DATA   | 0x02   | （不用于命令帧，仅作参考）     |
| VERIFY | 0x03   | [1-4] = 预期 CRC32 (uint32)  |
| RESET  | 0x04   | 无参数                       |
| QUERY  | 0x05   | 无参数                       |
| ABORT  | 0x06   | 无参数                       |

### 2.3 数据帧格式 (CAN ID = 0x101)

```
字节    内容            说明
[0]     序列号          0x00-0xFF，递增
[1]     有效长度        本帧有效数据字节数 (1-4)
[2-5]   数据载荷        最多 4 字节
[6-7]   CRC16           字节[0-5] 的 CRC16 校验（小端序）
```

每帧最多传输 4 字节有效数据。固件按每帧 4 字节拆分发送。

### 2.4 应答帧格式 (CAN ID = 0x102)

```
字节    内容            说明
[0]     ACK/NAK         0x00=ACK, 0x01=NAK
[1]     状态码          OTA_ACK_xxx
[2]     确认的序列号     对应数据帧的序列号
[3-7]   保留            0x00
```

| 状态码       | 值   | 含义                 |
|-------------|------|---------------------|
| OK          | 0x00 | 成功                 |
| CRC_ERR     | 0x01 | CRC 校验失败          |
| SEQ_ERR     | 0x02 | 序列号错误            |
| FLASH_ERR   | 0x03 | Flash 写入失败        |
| LEN_ERR     | 0x04 | 长度错误              |
| VERIFY_OK   | 0x05 | CRC32 验证通过        |
| VERIFY_FAIL | 0x06 | CRC32 验证失败        |
| BUSY        | 0x07 | 设备忙               |
| SESSION_END | 0x08 | 会话结束，将复位       |

## 3. 状态机设计

### 3.1 Bootloader 状态流转

```
                    +--------+
                    |  IDLE  |<-----------+
                    +---+----+            |
                        |                 |
              OTA_START |                 | ABORT / 超时
                        v                 |
                    +--------+            |
                    | READY  |----------->+
                    +---+----+
                        |
                  DATA  |
                        v
                    +---------+
                    |RECEIVING|<---+
                    +----+----+    |
                         |        | DATA (继续接收)
           VERIFY / 全部  |        |
             接收完成     v        |
                    +---------+    |
                    |VERIFYING|----+
                    +----+----+
                         |
                   CRC32 |
                     匹配 |
                         v
                    +--------+
                    |  DONE  |-----> 跳转 APP
                    +--------+

  任何状态收到 ABORT --> IDLE
  错误超过 10 次 --> ERROR --> IDLE
```

### 3.2 状态说明

| 状态       | 描述                              | 可接收的命令           |
|-----------|-----------------------------------|----------------------|
| IDLE      | 等待 OTA 开始命令                   | START, QUERY         |
| READY     | 已收到 START，等待数据               | DATA, ABORT, QUERY   |
| RECEIVING | 正在接收数据包                       | DATA, VERIFY, ABORT  |
| VERIFYING | 收到 VERIFY，校验 CRC32             | (自动完成)            |
| DONE      | 升级完成，准备跳转 APP                | (自动跳转)            |
| ERROR     | 错误状态，等待重试或超时               | START, ABORT, QUERY  |

## 4. 升级流程时序图

```
    主机 (Host)                           设备 (MCU Bootloader)
        |                                        |
        |  ====== 上电 / 复位 ======               |
        |                                        |
        |                               [检查 OTA 标志]
        |                               [初始化 CAN]
        |                               [启动 10s 超时]
        |                                        |
        |--- QUERY (0x100, CMD=0x05) ----------->|
        |                                        |
        |<-- ACK (state=IDLE) -------------------|
        |                                        |
        |--- START (0x100, CMD=0x01, size=N) --->|
        |                                        |
        |                               [验证 size]
        |                               [擦除 APP_A]
        |                                        |
        |<-- ACK (OK) ---------------------------|
        |                                        |
        |--- DATA[0] (0x101, seq=0, 4B) -------->|
        |                               [校验 CRC16]
        |                               [检查序列号]
        |                               [写入 Flash]
        |                               [回读验证]
        |<-- ACK (OK, seq=0) --------------------|
        |                                        |
        |--- DATA[1] (0x101, seq=1, 4B) -------->|
        |<-- ACK (OK, seq=1) --------------------|
        |                                        |
        |          ... (重复传输) ...              |
        |                                        |
        |--- DATA[N] (0x101, seq=N, 4B) -------->|
        |<-- ACK (OK, seq=N) --------------------|
        |                                        |
        |--- VERIFY (0x100, CMD=0x03, CRC32) --->|
        |                               [计算 APP CRC32]
        |                               [比较 CRC32]
        |                                        |
        |<-- ACK (VERIFY_OK) --------------------|
        |                               [清除 OTA 标志]
        |                               [跳转 APP]
        |                                        |
```

### 4.1 错误重传流程

```
    主机                                 设备
    |                                    |
    |--- DATA[5] (seq=5, CRC错误) ------>|
    |                                    |
    |<-- NAK (CRC_ERR, seq=5) ----------|
    |                                    |
    |--- DATA[5] (seq=5, 重传) --------->|
    |                                    |
    |<-- ACK (OK, seq=5) ---------------|
```

### 4.2 序列号错误处理

```
    主机                                 设备
    |                                    |
    |--- DATA[3] (seq=3, 但期望 seq=5)-->|
    |                                    |
    |<-- NAK (SEQ_ERR, seq=3) ----------|
    |                                    |
    |--- DATA[5] (seq=5, 正确重发) ----->|
    |                                    |
    |<-- ACK (OK, seq=5) ---------------|
```

## 5. 错误处理与回滚策略

### 5.1 错误类型及处理

| 错误类型         | 处理方式                                    |
|-----------------|-------------------------------------------|
| CRC16 校验失败   | 返回 NAK，主机重传该帧                       |
| 序列号不匹配     | 返回 NAK，主机从正确序列号重传                 |
| Flash 擦除失败   | 返回 NAK，状态转为 ERROR                    |
| Flash 写入失败   | 返回 NAK，状态转为 ERROR                    |
| 回读验证失败     | 返回 NAK，状态转为 ERROR                    |
| CRC32 验证失败   | 返回 NAK(VERIFY_FAIL)，升级失败             |
| 连续错误 ≥ 10 次 | 状态转为 ERROR，等待重新 START               |
| 超时 (10 秒)     | 跳转到已有 APP（如果有效）                    |

### 5.2 回滚策略（v1）

v1 版本采用单 APP 分区，回滚策略如下：

1. **升级前**: APP 中调用 `ota_trigger_request()` 写标志位并复位
2. **升级中**: 如果 OTA 失败（超时或错误），Bootloader 检查原 APP 是否有效
   - 原 APP 有效 → 跳转原 APP（回滚成功）
   - 原 APP 无效 → 等待新的 OTA 传输
3. **升级后**: 如果新 APP 运行异常，需通过 CAN 发送 ABORT 命令中断，然后重新升级

**注意**: v1 不支持 A/B 双分区热切换。如需完整回滚，后续版本可启用 APP_B 分区。

## 6. APP 端触发升级流程

### 6.1 触发方式

APP 通过以下步骤触发 OTA 升级：

```
1. 调用 ota_trigger_request()
2.   -> 擦除 OTA 标志位区域
3.   -> 写入 OTA_FLAG_MAGIC_REQUEST (0x544F4152)
4.   -> 调用 NVIC_SystemReset() 触发系统复位
5. 系统复位后，Bootloader 启动
6.   -> 检测到 OTA 标志位
7.   -> 进入 OTA 模式，等待主机升级数据
```

### 6.2 代码调用示例

```c
#include "ota_trigger.h"

/* 在 CAN 命令处理或按键回调中 */
void on_ota_command_received(void)
{
    /* 可选：保存当前状态到备份寄存器 */
    /* ... */

    /* 触发 OTA 升级（不会返回） */
    ota_trigger_request();
}
```

### 6.3 注意事项

- `ota_trigger_request()` 调用后不会返回，系统将立即复位
- 调用前应保存必要的运行状态（如备份寄存器、EEPROM 等）
- 确保 CAN 总线已连接主机且主机已准备好发送固件
- OTA 标志位使用 Flash 存储，受擦写次数限制（约 10 万次）

## 7. Bootloader 启动流程

```
            系统上电 / 复位
                  |
                  v
          [系统时钟初始化]
                  |
                  v
          [检查 OTA 标志位]
            /            \
      有 OTA 请求      无 OTA 请求
           |                |
           v                v
    [擦除 OTA 标志]   [检查 APP 有效性]
    [初始化 CAN]        /          \
    [进入 OTA 模式]  APP 有效     APP 无效
           |            |            |
           |            v            v
           |    [跳转 APP]    [进入 OTA 模式]
           |                       |
           v                       v
    [等待 CAN 数据]         [等待 CAN 数据]
    [10 秒超时检查]         [永久等待]
           |
     成功 / 超时 / 失败
      /       |       \
  成功     超时+APP有效  失败
    |         |          |
    v         v          v
 [跳转APP] [跳转APP] [等待重试]
```

## 8. CAN 波特率配置

默认 500Kbps，配置参数如下（APB1 = 180MHz）：

| 参数        | 值   | 说明                           |
|------------|------|-------------------------------|
| bittime_div | 18   | 时间片分频                      |
| BTS1        | 14   | 位时间段 1                      |
| BTS2        | 5    | 位时间段 2                      |
| SJW         | 3    | 同步跳转宽度                     |
| 总位时间     | 20   | 1 + BTS1 + BTS2 = 20 Tq       |
| 实际波特率   | 500K | 180MHz / (18 × 20) = 500Kbps  |

如需修改波特率，修改 `ota_config.h` 中的 `CAN_BAUDRATE_xxx` 宏定义。

## 9. 性能估算

- 每帧有效数据: 4 字节
- 48KB 固件需要: 48×1024 / 4 = 12288 帧
- CAN 500Kbps 理论传输时间: 每帧约 150bit → 12288 × 150 / 500000 ≈ 3.7 秒
- 含 ACK 响应和处理时间: 约 8-15 秒完成完整升级
