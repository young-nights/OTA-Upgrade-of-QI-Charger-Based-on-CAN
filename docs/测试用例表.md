## 四、测试方法说明

### 4.1 硬件测试环境

| 设备 | 用途 |
|------|------|
| SWD 调试器 (J-Link / DAP-Link) | 烧录、断点、寄存器查看 |
| 示波器 / 逻辑分析仪 | GPIO 翻转周期测量、时序验证 |
| CAN 转接卡 | 模拟 CCU 发送 UDS 指令 |
| 万用表 | 电流/电压基本测量 |

### 4.2 软件测试方法

#### 方法一：GPIO 翻转 + 示波器（推荐）

```c
// 在回调中翻转 GPIO 用于示波器测量
volatile uint32_t cb_count = 0;
void test_callback(void)
{
  cb_count++;
  gpio_toggle(GPIOA, GPIO_PINS_0);  // PA0 翻转
}

// 在 main 中创建定时器
uint8_t tmr_test = timer_create(100, test_callback, 1);  // 100ms 周期
timer_start(tmr_test);
```

用示波器测量 PA0 波形，周期应为 200ms（100ms 翻转一次，高低各 100ms）。

#### 方法二：调试器断点 + 变量观察

1. Keil MDK 中设置断点在回调函数入口
2. 观察 `cb_count` 变量递增
3. 观察 `timer_get_tick()` 返回值

#### 方法三：串口打印（需 UART 驱动就绪）

```c
// 在主循环中定期打印状态
static uint32_t last_print = 0;
if (timer_get_tick() - last_print >= 1000)
{
  last_print = timer_get_tick();
  printf("tick=%lu, cb_count=%lu\n", timer_get_tick(), cb_count);
}
```

## 五、Bootloader-only 模式 CAN-UDS 通信测试用例

> **前置条件**：仅烧录 Bootloader，不烧录 APP 固件。MCU 上电后检测到无有效 APP，自动进入 Safe Mode。
> **CAN ID**：请求 `0x18DA0D03`，响应 `0x18DA030D`
> **格式说明**：`0N` = ISO-TP 单帧 PCI（N = UDS 数据字节数），后面为 UDS 载荷，`00` 为填充

### 5.1 读 DID / 基础服务

#### 读软件版本（0xF189，确认会话和 DID）

发送：
```
18DA0D03 03 22 F1 89 00 00 00 00
```
期望：
```
18DA030D 08 62 F1 89 31 2E 30 2E 30 00
```
> 解析：版本 "1.0.0"（ASCII: 0x31 0x2E 0x30 0x2E 0x30）

#### 读 Bootloader 版本（0xF18D）

发送：
```
18DA0D03 03 22 F1 8D 00 00 00 00
```
期望：
```
18DA030D 08 62 F1 8D 31 2E 30 2E 30 00
```

#### 读固件类型（0x2010）

发送：
```
18DA0D03 03 22 20 10 00 00 00 00
```
期望：
```
18DA030D 04 62 20 10 XX 00 00 00
```
> 解析：XX = 0x01(APP) / 0x02(资源包) / 0x03(Bootloader)

#### 读 OTA 状态（0x2112）

发送：
```
18DA0D03 03 22 21 12 00 00 00 00
```
期望：
```
18DA030D 04 62 21 12 XX 00 00 00
```
> 解析：XX = 0x00(空闲) / 0x01(下载中)

#### 读活动槽位（0x2113）

发送：
```
18DA0D03 03 22 21 13 00 00 00 00
```
期望：
```
18DA030D 04 62 21 13 XX 00 00 00
```
> 解析：XX = 0x00(A) / 0x01(B)

#### 读待定槽位（0x2114）

发送：
```
18DA0D03 03 22 21 14 00 00 00 00
```
期望：
```
18DA030D 04 62 21 14 XX 00 00 00
```
> 解析：XX = 0x00(A) / 0x01(B) / 0xFE(无)

#### 读最近启动原因（0x2115）

发送：
```
18DA0D03 03 22 21 15 00 00 00 00
```
期望：
```
18DA030D 04 62 21 15 XX 00 00 00
```
> 解析：XX = 0x00(上电) / 0x02(WDG) / 0x03(OTA) / 0x04(回滚)

#### 读回滚计数器（0x2116）

发送：
```
18DA0D03 03 22 21 16 00 00 00 00
```
期望：
```

```
> 解析：XX = 回滚次数（出厂后累计）

#### 多 DID 读取（0xF189 + 0xF18D）

发送：
```
18DA0D03 05 22 F1 89 F1 8D 00 00
```

18DA030D 10 0A 62 F1 89 31 2E 30
18DA030D 21 2E 30 00 62 F1 8D 31

### 5.5 安全访问（0x27）

> 安全访问使用 ECDSA P-256 签名验证。流程：
> 1. 请求种子（0x27 0x01）→ 返回 4 字节随机种子
> 2. 分帧传输签名（0x27 0x03）→ 64 字节签名，每帧 6 字节，共约 11 帧
> 3. 验签请求（0x27 0x02）→ MCU 验证 ECDSA P-256 签名

#### Step 1: 请求种子

发送：
```
18DA0D03 02 27 01 00 00 00 00 00
```
期望：
```
18DA030D 06 67 01 SS SS SS SS 00
```
> SS SS SS SS = 4 字节随机种子（每次不同）

#### Step 2: 传输签名（0x27 0x03，分 11 帧）

> 签名共 64 字节，每帧传输 6 字节，blockSeq 从 0x01 递增。

**第 1 帧（blockSeq=0x01）：**

发送：
```
18DA0D03 08 27 03 01 AA AA AA AA
         AA AA 00
```
期望：
```
18DA030D 03 67 03 01 00 00 00 00
```
> AA = 签名数据字节 0~5

**第 2 帧（blockSeq=0x02）：**

发送：
```
18DA0D03 08 27 03 02 BB BB BB BB
         BB BB 00
```
期望：
```
18DA030D 03 67 03 02 00 00 00 00
```
> BB = 签名数据字节 6~11

**第 3~10 帧（blockSeq=0x03~0x0A）：** 格式同上，每帧 6 字节签名数据

**第 11 帧（blockSeq=0x0B，最后一帧）：**

发送：
```
18DA0D03 06 27 03 0B CC CC CC CC
         CC CC 00
```
期望：
```
18DA030D 03 67 03 0B 00 00 00 00
```
> CC = 签名数据字节 60~63（最后 4 字节，其余为 0x00 填充）

#### Step 3: 验签请求

发送：
```
18DA0D03 02 27 02 00 00 00 00 00
```
期望（成功）：
```
18DA030D 02 67 02 00 00 00 00 00
```
期望（签名无效，NRC 0x35）：
```
18DA030D 03 7F 27 35 00 00 00 00
```
期望（超过尝试次数，NRC 0x36）：
```
18DA030D 03 7F 27 36 00 00 00 00
```
> 连续 3 次失败后锁定 60 秒，期间再请求返回 NRC 0x37

#### 已解锁时请求种子（返回全零）

发送：
```
18DA0D03 02 27 01 00 00 00 00 00
```
期望：
```
18DA030D 06 67 01 00 00 00 00 00
```
> 已解锁状态返回 seed=0，表示无需再次认证

#### 未请求种子直接验签（NRC 0x12）

发送：
```
18DA0D03 02 27 02 00 00 00 00 00
```
期望：
```
18DA030D 03 7F 27 12 00 00 00 00
```

### 5.6 RoutineControl 例程控制（0x31）

> 擦除和编程依赖检查需要 Programming 会话 + SecurityAccess 解锁。

### 5.7 固件下载流程

> 完整流程：擦除 → RequestDownload → TransferData × N → TransferSignature → RequestTransferExit

#### RequestDownload（0x34）

**前置条件**：Programming 会话 + SecurityAccess + 已执行 0xFF00 擦除

发送（ISO-TP 多帧）：
```
18DA0D03 10 0F 34 00 44 08 00 50
         00 00 B8 00 00 00 00 00
```
期望（FC 流控后发送首帧）：
```
18DA030D 03 7F 34 78 00 00 00 00
```
期望（正响应）：
```
18DA030D 04 74 20 01 00 00 00 00
```
> 解析：
> - 0x34 = RequestDownload
> - 0x00 = dataFormatIdentifier
> - 0x44 = addressAndLengthFormatIdentifier（地址 4 字节，大小 4 字节）
> - 0x08005000 = APP_A 起始地址
> - 0x0000B800 = APP_A 大小 (46KB)
> - 响应 0x74 = 正响应，0x20 = LFI（2 字节 maxBlockLen），0x0100 = 256 字节

#### TransferData（0x36）首包

发送（ISO-TP 多帧，以 256 字节数据为例）：
```
18DA0D03 10 XX 36 01 [固件数据...]
         ...
```
期望：
```
18DA030D 02 76 01 00 00 00 00 00
```
> 0x01 = blockSequenceCounter（从 0x01 开始）

#### TransferData（0x36）后续包

发送：
```
18DA0D03 [ISO-TP] 36 02 [数据...]
```
期望：
```
18DA030D 02 76 02 00 00 00 00 00
```
> blockSeq 递增：0x01 → 0x02 → ... → 0xFF → 0x01（回绕，跳过 0x00）

#### TransferData 序号错误（NRC 0x73）

发送（故意跳过序号）：
```
18DA0D03 04 36 03 XX XX 00 00 00
```
期望（如果期望 seq=0x02 但收到 0x03）：
```
18DA030D 03 7F 36 73 00 00 00 00
```

#### TransferSignature（0x38）

> 签名共 64 字节，每帧 6 字节数据 + blockSeq，共 11 帧（格式同 0x27 0x03）

**第 1 帧（blockSeq=0x01）：**

发送：
```
18DA0D03 08 38 01 AA AA AA AA
         AA AA 00
```
期望：
```
18DA030D 02 78 01 00 00 00 00 00
```

**第 2~10 帧**：blockSeq 0x02~0x0A，格式同上

**第 11 帧（blockSeq=0x0B）：**

发送：
```
18DA0D03 06 38 0B CC CC CC CC
         CC CC 00
```
期望：
```
18DA030D 02 78 0B 00 00 00 00 00
```

#### RequestTransferExit（0x37）

发送：
```
18DA0D03 01 37 00 00 00 00 00 00
```
期望（NRC 0x78 先返回）：
```
18DA030D 03 7F 37 78 00 00 00 00
```
期望（验证通过）：
```
18DA030D 01 77 00 00 00 00 00 00
```
> MCU 执行：CRC32 校验 + 签名 patch + 镜像验证 + 元数据更新
> 完成后自动设置 trial_state=PENDING，准备试启动

#### RequestTransferExit 验证失败（NRC 0x72）

期望：
```
18DA030D 03 7F 37 72 00 00 00 00
```
> NRC 0x72 = GeneralProgrammingFailure（CRC/签名/长度校验失败）

### 5.8 WriteDataByIdentifier（0x2E）

> 仅支持 DID 0x2010（固件类型），需要 Programming 会话 + SecurityAccess

#### 写固件类型

发送：
```
18DA0D03 04 2E 20 10 01 00 00 00
```
期望：
```
18DA030D 03 6E 20 10 00 00 00 00
```
> 0x01 = APP 固件

#### 写不支持的值（NRC 0x31）

发送：
```
18DA0D03 04 2E 20 10 03 00 00 00
```
期望：
```
18DA030D 03 7F 2E 31 00 00 00 00
```
> 0x03（Bootloader）不被支持

### 5.9 异常场景

#### 不支持的 UDS 服务（NRC 0x11）

发送：
```
18DA0D03 02 14 01 00 00 00 00 00
```
期望：
```
18DA030D 03 7F 14 11 00 00 00 00
```
> 0x14（ClearDTC）不在 Bootloader 支持列表中

#### Default 会话下访问受保护服务（NRC 0x22）

发送：
```
18DA0D03 04 31 01 FF 00 00 00 00
```
期望：
```
18DA030D 03 7F 31 22 00 00 00 00
```
> NRC 0x22 = ConditionsNotCorrect（未切换到 Programming 会话）

### 5.10 S3 超时测试

> S3 超时 = 5000ms。非默认会话 5 秒无通信自动回退 Default 会话并清除安全状态。

**测试步骤**：
1. 发送 `18DA0D03 02 10 02 00 00 00 00 00` 切换到 Programming 会话
2. 等待 5 秒不发任何请求
3. 发送需要 Programming 会话的服务（如 `18DA0D03 04 31 01 FF 00 00 00 00`）
4. 期望返回 `18DA030D 03 7F 31 22 00 00 00 00`（已回退到 Default 会话）

## 六、测试环境与工具说明

### 6.1 Bootloader-only 测试环境

| 设备 | 用途 |
|------|------|
| SWD 调试器 (J-Link / DAP-Link) | 烧录 Bootloader、查看寄存器 |

| 120Ω 终端电阻 | CAN 总线匹配 |

### 6.2 Bootloader-only 测试覆盖范围

| 测试类别 | UDS 服务 | 会话要求 | 安全要求 |
|----------|----------|----------|----------|
| 基础通信 | 0x3E TesterPresent | 无 | 无 |
| 会话切换 | 0x10 SessionControl | 无 | 无 |
| MCU 复位 | 0x11 ECUReset | 无 | 无 |
| DID 读取 | 0x22 ReadDID (0xF189/0xF18D/0x2112~0x2116) | 无 | 无 |
| DID 写入 | 0x2E WriteDID (0x2010) | Programming | 需要 |
| 安全认证 | 0x27 SecurityAccess (ECDSA P-256) | 无 | — |
| 例程控制 | 0x31 RoutineControl (0xFF00/0xFF01) | Programming | 需要 |
| 固件下载 | 0x34/0x36/0x37/0x38 | Programming | 需要 |

### 6.3 Bootloader Safe Mode 行为说明

| 场景 | 行为 |
|------|------|
| 无有效 APP（两槽均无效） | 自动进入 Safe Mode |
| ota_state == DOWNLOADING | 自动进入 Safe Mode（断点续传） |
| Safe Mode 下会话管理 | 支持 Default/Programming/Extended 三种会话 |
| S3 超时 | 5000ms，超时后回退 Default 并清除安全状态 |
| SecurityAccess 锁定 | 连续 3 次失败 → 锁定 60 秒 |
| 切换会话 | 非默认会话间切换清除安全解锁状态 |
| 回退到默认会话 | 清除安全解锁 + 中止传输 + ota_state → IDLE |
