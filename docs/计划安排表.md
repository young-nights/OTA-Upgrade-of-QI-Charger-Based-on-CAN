## 三、当前待解决问题（2026-09-02）

### 🔴 P0：0x37 TransferExit 通信失败

**现象**：脚本发 `37`，MCU 收到后回 `7F 37 78`（一次），之后再无响应。

**根因链**：
1. Flash 写操作（0x36 TransferData）期间 CPU 停滞 → CAN 控制器进入 Bus-Off
2. 0x37 处理器发 0x78 → 成功（此时 CAN 尚可）
3. 主循环调 `safe_mode_finish_transfer_exit()` → 验签期间 pump 需发周期性 0x78
4. 旧代码用 `isotp_tx_send` 发 0x78 → Bus-Off 时阻塞 1s → 主循环卡死
5. 后续 0x78 / 0x77 全部发不出

**已修复（推送中）**：
- `safe_mode_send_pending` 改用 `can_driver_send` 直接发 SF 单帧（非阻塞）
- Bus-Off 恢复调 `can_driver_init()` 完整重建（含 bit timing + filter）
- 脚本 0x37 失败重试 5 次

**验证方法**：
1. Keil 重编 Bootloader → 烧录
2. ZCANPRO 总线监听：应看到周期性 `7F 37 78`（每 2s），验签完后 `77`
3. 全流程跑通 → OTA 成功

### 🟡 P1：复位后 APP 确认

**现状**：复位后用 DID 0x2113（单字节）轮询 8s，再检查 0x2010 / 0x34 NRC 0x11。

**风险**：如果 APP 跳转失败（HardFault），脚本 8s 后报错。总线监听应看到 `0x18FF260D` byte[1]=0x41。

### 🟢 P2：端到端回归测试

所有模块单独修完后，需跑完整 OTA 流程：
1. 只烧 Boot → OTA APP → 验证 APP 运行
2. APP 在线 → 触发 OTA Boot → 验证跳转
3. 异常场景：断电恢复、重复 OTA、空槽烧录
