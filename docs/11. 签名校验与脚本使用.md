# 11. 签名校验与脚本使用

> **适用**：理解 Bootloader 镜像签名校验机制、掌握打包/签名脚本用法、验证签名正确性
> **涉及文件**：`boot_verify.c/h`、`sha256.c/h`、`uECC.c/h`、`pack_image.py`、`merge_prod_bin.py`

---

## 1. 签名校验原理

Bootloader 在每次上电跳转 APP 前，对镜像执行 6 级校验，全部通过才允许跳转。

### 1.1 校验流程

```
boot_verify_image(base_addr, slot_size)
  │
  ├─ Step 1: Header Magic ─── "XATO" (0x4F544158)
  │     fail_step = 1
  │
  ├─ Step 2: Image Length ─── 不能为 0，不能超出 slot 容量
  │     fail_step = 2
  │
  ├─ Step 3: CRC32 ──────── IEEE 802.3 CRC 覆盖裸固件（不含头）
  │     fail_step = 3
  │
  ├─ Step 3b: Reset Handler ─ Reset 向量必须落在当前 slot 内
  │     fail_step = 4
  │
  ├─ Step 4: 公钥完整性 ──── 检查 .ecdsa_pubkey 段末尾 Magic "KEYP"
  │     fail_step = 5
  │
  └─ Step 5: ECDSA P-256 ─── SHA-256(裸固件) → uECC_verify(pubkey, hash, sig)
        fail_step = 6
```

### 1.2 失败诊断码

`g_verify_fail_step` 变量记录最后失败的步骤：

| 值 | 含义               | 常见原因                                  |
| -- | ------------------ | ----------------------------------------- |
| 0  | 校验通过           | —                                        |
| 1  | Magic 错误         | 镜像头损坏、烧录地址偏移、裸 bin 直接烧入 |
| 2  | 长度越界           | image_length 为 0 或超出 slot 容量        |
| 3  | CRC32 不匹配       | 固件数据被篡改或传输错误                  |
| 4  | Reset Handler 越界 | 镜像链接到错误 slot（A 链 B 或反之）      |
| 5  | 公钥损坏           | Flash 被意外擦写，公钥区 Magic 不匹配     |
| 6  | ECDSA 签名无效     | 私钥与公钥不匹配、签名被篡改、数据损坏    |

### 1.3 密钥体系

| 组件 | 算法                    | 说明                                                                            |
| ---- | ----------------------- | ------------------------------------------------------------------------------- |
| 公钥 | ECDSA P-256 (secp256r1) | 65 字节 SEC1 未压缩格式`04 \|\| X \|\| Y`，烧写在 Bootloader `.ecdsa_pubkey` 段 |
| 私钥 | ECDSA P-256             | 仅存在于`docs/keys/private.pem`，**不允许烧入 MCU**                     |
| 哈希 | SHA-256                 | 对裸固件（不含 256 字节头）计算，产出 32 字节摘要                               |
| 签名 | IEEE P1363              | `R \|\| S` 各 32 字节 = 64 字节，存放在镜像头 `signature` 字段                |

**关键约束**：

- 签名对象 = 裸固件数据，**不含** 256 字节 XATO 头
- 公钥编译时固化在 Bootloader 中，量产时**不可更换**
- 私钥必须严格保密，仅用于开发/产线打包

### 1.4 镜像头布局（256 字节）

与 `boot_verify.h` 中 `image_header_t` 定义一致：

| 偏移 | 长度 | 字段            | 说明                          |
| ---- | ---- | --------------- | ----------------------------- |
| 0x00 | 4    | magic           | `0x4F544158` ("XATO"，小端) |
| 0x04 | 4    | image_length    | 裸固件字节数（不含头）        |
| 0x08 | 4    | crc32           | 裸固件 CRC32 (IEEE 802.3)     |
| 0x0C | 64   | signature       | ECDSA P-256 R\|\|S            |
| 0x4C | 16   | version         | 版本字符串，如 "1.0.0\0"      |
| 0x5C | 4    | build_timestamp | 打包时的 Unix 时间戳          |
| 0x60 | 160  | reserved        | 填 0                          |

## 2. 密钥生成

### 2.1 生成新密钥对

```Java
# 生成 ECDSA P-256 私钥
openssl ecparam -genkey -name prime256v1 -noout -out docs/keys/private.pem

# 提取公钥（用于对比 / 验证）
openssl ec -in docs/keys/private.pem -pubout -out docs/keys/public.pem
```

### 2.2 从私钥提取公钥坐标（写入 Bootloader 用）

```bash
# 查看私钥详情（含公钥坐标）
openssl ec -in docs/keys/private.pem -text -noout
```

输出示例：

```
pub:
    04:79:0d:96:ca:91:2d:90:db:73:df:21:b0:6e:e7:
    ce:19:aa:7c:1f:75:30:55:0a:48:21:84:19:b4:4b:
    4c:37:cb:f5:7c:d3:fc:9e:26:be:1b:a6:94:dd:45:
    62:7e:aa:ca:71:38:f5:7a:8e:a8:d5:dd:20:70:33:
    26:f0:95:41:71
```

将 `04:` 后的 64 字节十六进制填入 `boot_verify.c` 的 `g_ecdsa_public_key[65]` 数组：

- 第 1 字节固定为 `0x04`（未压缩点标记）
- 第 2~33 字节 = X 坐标
- 第 34~65 字节 = Y 坐标

### 2.3 验证密钥对匹配

```bash
# 用私钥签名任意数据，再用公钥验证
echo "test" > /tmp/test.bin
openssl dgst -sha256 -sign docs/keys/private.pem -out /tmp/test.sig /tmp/test.bin
openssl dgst -sha256 -verify docs/keys/public.pem -signature /tmp/test.sig /tmp/test.bin
# 输出 "Verified OK" 表示密钥对匹配
```

### 2.4 当前仓库默认密钥

`docs/keys/` 下已包含默认开发密钥：

- `private.pem` — ECDSA P-256 私钥
- `public.pem` — 对应公钥

**量产时必须替换为正式密钥对。**

## 3. 打包脚本使用

### 3.1 `pack_image.py` — 裸 bin → 签名镜像

路径：`qi_wireless_bootloader/tools/pack_image.py`

功能：读取 Keil 产出的裸 `.bin`，计算 CRC32 + ECDSA P-256 签名，写入 256 字节 XATO 头，输出 `.ota.bin`。

**基本用法**（在仓库根目录执行）：

```bash
cd qi_wireless_bootloader/tools
python pack_image.py
```

**显式指定参数**：

```bash
python pack_image.py \
  --bin ../../qi_wireless_code/mdk_project/Objects/qi_wireless.bin \
  --key ../../docs/keys/private.pem \
  --out ../../qi_wireless_code/mdk_project/Objects/app_slot_a.ota.bin \
  --version 1.0.0
```

| 参数          | 默认值                                                      | 说明                           |
| ------------- | ----------------------------------------------------------- | ------------------------------ |
| `--bin`     | `qi_wireless_code/mdk_project/Objects/qi_wireless.bin`    | Keil fromelf 产出的裸 APP .bin |
| `--key`     | `docs/keys/private.pem`                                   | ECDSA P-256 私钥 PEM           |
| `--out`     | `qi_wireless_code/mdk_project/Objects/app_slot_a.ota.bin` | 输出镜像路径                   |
| `--version` | `1.0.0`                                                   | 写入头的版本字符串             |

**成功输出示例**：

```
输出: /path/to/app_slot_a.ota.bin
总长: 48128  (头 256 + 固件 47872)
链接: Slot A  → 产线烧录地址 0x08005000
```

**常见错误**：

| 提示        | 原因                             | 处理                            |
| ----------- | -------------------------------- | ------------------------------- |
| 找不到固件  | 还没 fromelf 出 .bin，或路径不对 | 先在 Keil 中 Rebuild            |
| 找不到私钥  | `docs/keys/private.pem` 不存在 | 按第 2 节生成密钥               |
| 超过槽大小  | 裸 bin > 0xB700 (46848 字节)     | 减小 APP 代码                   |
| 链接 Slot B | Target IROM1 不是 0x08005100     | 改 Keil Target IROM1 后 Rebuild |

### 3.2 `merge_prod_bin.py` — Boot + APP 合并

路径：`python_tools/merge_prod_bin.py`

功能：将 `bootloader.bin` + `app_slot_a.ota.bin` 合并为一个 `prod_image.bin`，用于产线烧录。

```bash
cd python_tools
python merge_prod_bin.py
```

| 参数       | 默认值                                                        | 说明               |
| ---------- | ------------------------------------------------------------- | ------------------ |
| `--boot` | `qi_wireless_bootloader/mdk_project/Objects/bootloader.bin` | Bootloader 二进制  |
| `--app`  | `qi_wireless_code/mdk_project/Objects/app_slot_a.ota.bin`   | 已签名的 APP 镜像  |
| `--out`  | `python_tools/prod_image.bin`                               | 合并输出           |
| `--hex`  | —                                                            | 同时生成 Intel HEX |

**布局**：

```
0x0000  Bootloader  20KB (不足 20KB 补 0xFF)
0x5000  Slot A      (含 256B XATO 头 + 固件)
```

合并后的 `prod_image.bin` 从 **`0x08000000`** 整体烧录。

### 3.3 完整产线打包流程

```
Keil Rebuild → fromelf → qi_wireless.bin (裸 bin)
                            │
                  pack_image.py (--key private.pem)
                            │
                  app_slot_a.ota.bin (XATO 头 + 签名 + 固件)
                            │
                  merge_prod_bin.py (--boot bootloader.bin)
                            │
                  prod_image.bin (Boot + Slot A)
                            │
                  J-Link / AT32 ISP 从 0x08000000 烧录
```

## 4. 签名校验测试方法

### 4.1 离线验证（PC 端）

#### 4.1.1 验证镜像头完整性

```python
import struct

with open("app_slot_a.ota.bin", "rb") as f:
    header = f.read(256)

magic = struct.unpack("<I", header[0:4])[0]
img_len = struct.unpack("<I", header[4:8])[0]
crc32 = struct.unpack("<I", header[8:12])[0]
version = header[0x4C:0x5C].rstrip(b"\x00").decode()

print(f"Magic: 0x{magic:08X} (expect 0x4F544158)")
print(f"Image length: {img_len}")
print(f"CRC32: 0x{crc32:08X}")
print(f"Version: {version}")
```

#### 4.1.2 验证 CRC32

```python
import binascii

with open("app_slot_a.ota.bin", "rb") as f:
    header = f.read(256)
    firmware = f.read()

stored_crc = struct.unpack("<I", header[8:12])[0]
computed_crc = binascii.crc32(firmware) & 0xFFFFFFFF

print(f"Stored CRC32:    0x{stored_crc:08X}")
print(f"Computed CRC32:  0x{computed_crc:08X}")
print(f"Match: {stored_crc == computed_crc}")
```

#### 4.1.3 验证 ECDSA 签名（OpenSSL）

```bash
# 提取固件数据（跳过 256 字节头）
tail -c +257 app_slot_a.ota.bin > /tmp/firmware.bin

# 提取签名（偏移 0x0C，长度 64 字节）
dd if=app_slot_a.ota.bin bs=1 skip=12 count=64 of=/tmp/signature.bin

# 将 IEEE P1363 签名转为 DER 格式（OpenSSL 要求）
python3 -c "
import struct
with open('/tmp/signature.bin', 'rb') as f:
    r = int.from_bytes(f.read(32), 'big')
    s = int.from_bytes(f.read(32), 'big')

def int_to_der_int(n):
    b = n.to_bytes(32, 'big').lstrip(b'\x00')
    if b[0] & 0x80:
        b = b'\x00' + b
    return b'\x02' + bytes([len(b)]) + b

r_der = int_to_der_int(r)
s_der = int_to_der_int(s)
seq = r_der + s_der
der_sig = b'\x30' + bytes([len(seq)]) + seq
with open('/tmp/signature.der', 'wb') as f:
    f.write(der_sig)
"

# 计算 SHA-256 哈希
openssl dgst -sha256 -binary /tmp/firmware.bin > /tmp/hash.bin

# 用公钥验证
openssl pkeyutl -verify -pubin -inkey docs/keys/public.pem \
  -sigfile /tmp/signature.der -in /tmp/hash.bin -pkeyopt digest:sha256
# 输出 "Signature Verified Successfully" 表示通过
```

### 4.2 板端测试（MCU 端）

#### 4.2.1 正常跳转测试

| 步骤 | 操作                           | 预期结果                              |
| ---- | ------------------------------ | ------------------------------------- |
| 1    | 烧录合并后的`prod_image.bin` | 烧录成功                              |
| 2    | 复位上电                       | `g_verify_fail_step == 0`，跳转 APP |
| 3    | 读`0x22 F195`                | 返回版本字符串 "1.0.0"                |

#### 4.2.2 签名无效测试

| 步骤 | 操作                   | 预期结果                                    |
| ---- | ---------------------- | ------------------------------------------- |
| 1    | 用错误私钥重新签名打包 | 生成无效镜像                                |
| 2    | 烧录到 Slot A          | 烧录成功                                    |
| 3    | 复位上电               | `g_verify_fail_step == 6`，停在 Safe Mode |
| 4    | 串口/SWD 读 fail_step  | 返回 6（ECDSA 失败）                        |

#### 4.2.3 CRC 篡改测试

| 步骤 | 操作                                          | 预期结果                                  |
| ---- | --------------------------------------------- | ----------------------------------------- |
| 1    | 用十六进制编辑器修改镜像中任意 1 字节固件数据 | —                                        |
| 2    | 保持原 CRC32 和 signature 不变                | —                                        |
| 3    | 烧录到 Slot A                                 | 烧录成功                                  |
| 4    | 复位上电                                      | `g_verify_fail_step == 3`，CRC 校验失败 |

#### 4.2.4 Magic 篡改测试

| 步骤 | 操作                               | 预期结果                                    |
| ---- | ---------------------------------- | ------------------------------------------- |
| 1    | 修改镜像头前 4 字节为非`XATO` 值 | —                                          |
| 2    | 烧录到 Slot A                      | 烧录成功                                    |
| 3    | 复位上电                           | `g_verify_fail_step == 1`，Magic 校验失败 |

#### 4.2.5 Reset Handler 越界测试

| 步骤 | 操作                                   | 预期结果                                        |
| ---- | -------------------------------------- | ----------------------------------------------- |
| 1    | 编译 Slot A 的固件（IROM1=0x08005100） | —                                              |
| 2    | 强制烧录到 Slot B（0x08010800）        | —                                              |
| 3    | 复位上电                               | `g_verify_fail_step == 4`，Reset Handler 越界 |

### 4.3 JTAG/SWD 调试验证

在调试器中检查以下变量：

```
# 变量名               | 内存地址（参考值）    | 含义
g_verify_fail_step     | 见 .map 文件         | 0=通过，1~6=失败步骤
g_ecdsa_public_key     | .ecdsa_pubkey 段     | 65 字节公钥
g_pubkey_magic         | 公钥后 4 字节        | 0x4B594550 ("KEYP")
```

**Watch 监视建议**：

- `g_verify_fail_step` — 核心诊断变量
- `header->magic` / `header->image_length` / `header->crc32` — 镜像头字段
- 单步进入 `boot_verify_image()` 观察每步返回值

### 4.4 自动化测试脚本框架

```python
#!/usr/bin/env python3
"""离线签名校验自动化测试（不需要 MCU）。"""

import hashlib
import struct
import subprocess
import sys
import os

def test_header_magic(image_path):
    """测试 1: Magic 校验"""
    with open(image_path, "rb") as f:
        magic = struct.unpack("<I", f.read(4))[0]
    assert magic == 0x4F544158, f"Magic 错误: 0x{magic:08X}"
    print("[PASS] Header Magic 正确")

def test_image_length(image_path):
    """测试 2: 长度校验"""
    with open(image_path, "rb") as f:
        f.seek(4)
        img_len = struct.unpack("<I", f.read(4))[0]
    total = os.path.getsize(image_path)
    assert 0 < img_len <= total - 256, f"长度越界: {img_len}"
    print(f"[PASS] Image Length 正确: {img_len} bytes")

def test_crc32(image_path):
    """测试 3: CRC32 校验"""
    import binascii
    with open(image_path, "rb") as f:
        header = f.read(256)
        firmware = f.read()
    stored = struct.unpack("<I", header[8:12])[0]
    computed = binascii.crc32(firmware) & 0xFFFFFFFF
    assert stored == computed, f"CRC 不匹配: 0x{stored:08X} != 0x{computed:08X}"
    print(f"[PASS] CRC32 正确: 0x{stored:08X}")

def test_version(image_path):
    """测试 5: 版本字段"""
    with open(image_path, "rb") as f:
        f.seek(0x4C)
        ver = f.read(16).rstrip(b"\x00").decode()
    assert ver, "版本为空"
    print(f"[PASS] Version: {ver}")

if __name__ == "__main__":
    path = sys.argv[1] if len(sys.argv) > 1 else "app_slot_a.ota.bin"
    test_header_magic(path)
    test_image_length(path)
    test_crc32(path)
    test_version(path)
    print("\n全部测试通过。")
```

## 5. 常见问题

| 问题                      | 原因                                   | 解决方案                                                |
| ------------------------- | -------------------------------------- | ------------------------------------------------------- |
| Bootloader 停在 Safe Mode | 镜像校验失败                           | 检查`g_verify_fail_step` 确定失败步骤                 |
| 签名后验证仍然失败        | 私钥与公钥不匹配                       | 重新生成密钥对，确保 PEM 与`boot_verify.c` 中公钥对应 |
| 签名验证耗时过长          | 纯软件 ECDSA P-256 在 M4F 上约 30~50ms | 属于正常范围，不影响启动（单次验证）                    |
| SHA-256 哈希不一致        | 签名时和验证时的数据范围不同           | 确保签名对象 = 裸固件（不含 256 字节头）                |
| 公钥损坏 (fail_step=5)    | Flash 意外擦写                         | 检查`.ecdsa_pubkey` 段是否被代码覆盖                  |
| 镜像链接到错误 slot       | IROM1 地址设置错误                     | Slot A 用 0x08005100，Slot B 用 0x08010900              |

## 6. 安全注意事项

1. **私钥保护**：`docs/keys/private.pem` 不允许进入版本控制的公开分支，生产环境应使用离线签名工站
2. **公钥不可替换**：Bootloader 中的公钥编译后固化在 Flash 中，量产时不可通过 OTA 更换
3. **密钥轮换**：如需更换密钥，必须重新烧录所有 Bootloader
4. **签名不可伪造**：没有正确私钥无法生成合法签名，恶意固件无法通过校验
