# Bootloader Safe Mode 下载顺序

适用：`qi_wireless_bootloader` 已进入 `enter_safe_mode()`（空片、双槽无效，或 metadata 为 `DOWNLOADING`）。

请求 ID 一律 `0x18DA0D03`，响应 ID `0x18DA030D`，扩展帧，经典 CAN 250 kbps，DLC=8。**第 1 字节必须是 ISO-TP PCI**。

> **注意**: 擦槽操作 (`31 01 FF00`) 只擦除固件 Slot 区域，不会擦除 Device Info 保留区 (`0x0801D000` ~ `0x0801DFFF`)。Bootloader 在执行擦除时会校验目标地址，拒绝擦除 Device Info 区域，从而保护 SN 序列号等设备信息在 OTA 升级后仍然保留。

---

## 必做顺序（代码硬门禁）

```
10 02 编程会话
  → 27 01 要 seed
  → 27 03 分片送 64B 签名  （或一条 ISO-TP 多帧 27 02）
  → 27 02 验签
  → 2E 2010 01 选 APP
  → 31 01 FF00 擦槽          ← 不擦直接 34 会 NRC 0x24
  → 34 申请下载
  → 36 按块写镜像            ← 必须是 pack_image.py 打的包（256B 头 + 固件）
  → 37 结束传输并验签
  → 11 01 复位进试用
```

过程中超过 5 s 没有 UDS，会掉回 Default Session，下载中止。长步骤前后插 TesterPresent：

```
02 3E 00 00 00 00 00 00
```

擦 Flash / 验签会先回 `7F xx 78`（ResponsePending），再出最终正响应。超时放到 8～10 s。

---

## 逐步 CAN 数据（ZCANPRO 普通发送）

| 步 | 作用 | 发出（8 字节） | 期望 `18DA030D` |
|---|---|---|---|
| 1 | Programming Session | `02 10 02 00 00 00 00 00` | `02 50 02 ...` |
| 2 | RequestSeed | `02 27 01 00 00 00 00 00` | `06 67 01 s0 s1 s2 s3` |
| 3 | 签名分片 ×16 | `07 27 03 ss d0 d1 d2 d3` | `03 67 03 ss ...` |
| 4 | SendKey 验签 | `02 27 02 00 00 00 00 00` | 可能先 `7F 27 78`，再 `02 67 02` |
| 5 | 固件类型 APP | `04 2E 20 10 01 00 00 00` | `03 6E 20 10 ...`（必须 `01`） |
| 6 | 擦非活跃槽 | `04 31 01 FF 00 00 00 00` | 先 `7F 31 78`，再 `04 71 01 FF 00` |
| 7 | RequestDownload | 见下文 | `04 74 20 01 00`（maxBlock=256） |
| 8 | TransferData | `36` + blockSeq + 数据 | `02 76 ss ...` |
| 9 | TransferExit | `01 37 00 00 00 00 00 00` | 先 `7F 37 78`，再 `01 77` |
| 10 | 复位 | `02 11 01 00 00 00 00 00` | `02 51 01`，然后 MCU 复位 |

先发第 1、2 步。能拿到 4 字节 seed，说明 Safe Mode + CAN-UDS 已经通，再往下做验签和擦写。

> **说明**: 上表第 6 步（擦槽）只擦除固件 Slot 区域，不会擦除 Device Info 保留区 (`0x0801D000` ~ `0x0801DFFF`)。SN 序列号等设备信息在 OTA 升级后仍然保留。

## 第 3 步：签名

对 **4 字节 seed**（大端 `s0 s1 s2 s3`）做 `SHA256`，再用仓库 `docs/keys/private.pem` 做 ECDSA P-256，得到 64 字节 `R‖S`（IEEE P1363，不是 DER）。必须与烧进 Bootloader 的公钥成对。

`ss` 从 `01` 到 `10`，每帧 4 字节签名（16 帧凑满 64 字节）。连续 3 次验签失败锁 30 s（`7F 27 36`）。切 Default Session **不会**清失败计数。

也可以一条 `27 02` + 64 字节走 ISO-TP 多帧（FF / 等 FC / CF）。ZCANPRO 普通发送要自己拆，实验室优先用 `0x27 0x03` 分片。

OpenSSL 示例（把 seed 换成实际值）：

```bash
printf '\xAA\xBB\xCC\xDD' | openssl dgst -sha256 -binary -out seed.hash
openssl pkeyutl -sign -inkey docs/keys/private.pem \
  -in seed.hash -pkeyopt digest:sha256 -out sa.der
# 再把 DER 转成 64 字节 R||S（与 pack_image.py 相同方式）
```

## 第 7 步：0x34 RequestDownload

只想点通正响应（不校验总长）：

```
02 34 00 00 00 00 00 00
```

正式刷写要带 ALFID 和 size。size = 打包文件总长（含 256 字节头），且 ≤ 槽大小 `0xA800`。地址字段会被读，但写入仍从槽基址开始。

未先发第 6 步擦除（`g_dl_erased=0`）直接 0x34 → NRC `0x24`。

示例（size = `0x00001000`，UDS 11 字节，要多帧）：

```
UDS: 34 00 44  00 00 00 00  00 00 10 00
     SID fmt ALFID  4B 地址(忽略)   4B 长度

FF:  10 0B 34 00 44 00 00 00
     等 MCU FC: 30 00 01 ...
CF:  21 00 00 00 10 00 00 00
```

---

## 第 8 步：0x36 TransferData

`blockSeq` 从 `01` 起，`FF` 下一帧是 `01`（跳过 `00`）。

镜像必须带 XATO 头（magic + length + CRC32 + 64B 头内签名 + 固件）。裸 Keil `.bin` 用 `python_tools/pack_image.py` 打包，或交给 `zcanpro_ext_ota.py` 现场打包，不要直接当 0x36 载荷。

单帧最多塞 5 字节数据：

```
07 36 01 d0 d1 d2 d3 d4
```

完整刷写应走 ISO-TP 多帧，每包 UDS = `36 ss` + 最多 254 字节（0x34 宣告 maxBlockLength=256）。

`0x38` 可跳过：打包时头里已有签名即可。

## ISO-TP 填写规则

单帧（UDS 长度 1～7）：

```
Byte0     Byte1..N        其余
PCI 0x0N  N 字节 UDS      00 或 CC 填充
```

负响应：

```
7F [SID] [NRC]
7F [SID] 78     ← ResponsePending
```

常见 NRC：`0x22` 会话不对，`0x24` 顺序错（未擦就 34），`0x31` 超范围（固件类型不是 01，或 size 过大），`0x33` 未解锁，`0x35` 签名错，`0x36` 次数超限。
