# 12. 签名原理与 Seed 机制

> **适用**：理解 ECDSA 非对称加密原理、UDS SecurityAccess Seed-Challenge 认证流程
> **涉及文件**：`boot_verify.c/h`、`boot_safe_mode.c`、`can_protocol.c`、`uECC.c/h`、`sha256.c/h`

---

## 1. ECDSA 私钥/公钥配对原理

本项目使用 **ECDSA P-256 (secp256r1)** 椭圆曲线非对称加密算法。

### 1.1 核心数学关系

```
公钥 = 私钥 × 椭圆曲线基点 G
```

| 组件 | 长度 | 说明 |
|------|------|------|
| 私钥 | 32 字节 | 随机整数，存储于 `docs/keys/private.pem` |
| 公钥 | 65 字节 | 椭圆曲线上的点 (X, Y)，格式 `04 \|\| X \|\| Y`，烧写于 Bootloader `.ecdsa_pubkey` 段 |

**不可逆性**：知道公钥无法反推私钥（椭圆曲线离散对数问题，计算上不可行）。

### 1.2 签名与验证流程

| 步骤 | 签名方（产线/PC） | 验证方（Bootloader） |
|------|-------------------|---------------------|
| 1 | 用 SHA-256 对数据取哈希 `h` | 同样对数据取 SHA-256 哈希 `h` |
| 2 | 用**私钥** + 随机数 k 对 `h` 运算 → 产出 64 字节签名 `(R, S)` | — |
| 3 | — | 用**公钥** + 哈希 `h` + 签名 `(R, S)` 运算 → 输出 1（有效）或 0（无效） |

**关键特性**：
- 私钥持有者能签名，公钥持有者能验证，**反过来不行**
- 同一份数据用不同随机数 k 签名，结果不同，但都有效
- 没有私钥就无法伪造签名（安全性的根基）

### 1.3 本项目中的两个用途

| 用途 | 签名对象 | 存储位置 | 验证时机 |
|------|----------|----------|----------|
| 镜像签名校验 (`boot_verify.c`) | 裸固件数据（不含 256B 头） | 镜像头 signature 字段 (偏移 0x0C) | 每次上电跳转 APP 前 |
| SecurityAccess 身份认证 (`0x27` 服务) | SHA-256(seed) | 运行时通过 CAN 发送 | OTA 升级前解锁 |

两者使用**同一把密钥对**：私钥在 PC/产线侧，公钥烧在 Bootloader 的 `.ecdsa_pubkey` 段。

## 2. Seed 机制（UDS 0x27 SecurityAccess）

### 2.1 什么是 Seed

Seed 是 MCU 在 SecurityAccess 服务中生成的**随机挑战值**（Challenge），本质上是一个 **nonce（Number used ONCE）**。

- 长度：4 字节
- 生成时机：Host 首次发送 `27 01` 时
- 用途：与签名绑定，防止重放攻击

### 2.2 完整交互流程

```
Host (PC/产线)                          MCU (Bootloader/APP)
    │                                        │
    │──── 27 01 (Request Seed) ─────────────>│
    │                                        │ generate_random_seed()
    │                                        │ → seed = 4字节随机数
    │<─── 67 01 [seed: 4 bytes] ────────────│
    │                                        │
    │  (本地计算)                             │
    │  hash = SHA-256(seed)                  │
    │  sig  = ECDSA_Sign(hash, private_key)  │
    │                                        │
    │──── 27 02 [sig: 64 bytes] ───────────>│
    │                                        │ hash = SHA-256(seed)
    │                                        │ result = uECC_verify(pubkey, hash, sig)
    │                                        │
    │<─── 67 02 (解锁成功) ─────────────────│   if result == 1 → security_unlocked = 1
    │    或 7F 27 35 (Invalid Key)           │   else → fail_count++
```

### 2.3 Seed 生成算法

```c
// boot_safe_mode.c / can_protocol.c
static uint32_t generate_random_seed(void)
{
    static uint32_t lfsr = 0x12345678U;     // LFSR 初始值
    uint32_t tick = timer_get_tick();         // SysTick 计数（时间熵源）

    lfsr ^= tick;                            // XOR 混入时间熵

    // 32-bit 最大长度 LFSR（tap: bit 31, 21, 1, 0）
    bit = ((lfsr >> 0) ^ (lfsr >> 1) ^ (lfsr >> 21) ^ (lfsr >> 31)) & 1U;
    lfsr = (lfsr >> 1) | (bit << 31);

    lfsr ^= (tick << 7) ^ (tick >> 13);     // 再次混合

    return lfsr;
}
```

**设计要点**：
- 使用 **LFSR（线性反馈移位寄存器）+ SysTick 时间戳** 生成伪随机 4 字节 seed
- 每次上电后第一次请求时生成，同一会话内复用（已解锁时按 ISO 14229 返回 seed=0）
- 对于安全访问场景，LFSR 的随机性已足够（seed 的作用是保证新鲜性，而非密码学安全随机数）

### 2.4 Seed 验证（MCU 端）

```c
// 验证逻辑（boot_safe_mode.c / can_protocol.c）
sha256_hash(g_seed, 4U, seed_hash);                              // 对 4 字节 seed 取 SHA-256
result = uECC_verify(public_key, seed_hash, g_sa_sig_buf);       // ECDSA 验签
```

Host 发回的 64 字节签名是**对 SHA-256(seed) 的 ECDSA 签名**，MCU 用预置公钥验证。

### 2.5 为什么需要 Seed

**核心目的：防止重放攻击（Replay Attack）。**

**假设没有 seed**：

```
攻击者抓到一次合法的 0x27 02 响应（64 字节签名）
→ 下次直接重放同一签名 → 解锁成功
```

**有 seed 后**：

```
每次 0x27 01 返回的 seed 不同
→ 同一个签名只对当次 seed 有效
→ 重放旧签名 → SHA-256(新seed) ≠ SHA-256(旧seed) → 验签失败
```

**Seed 保证了每次认证交互的唯一性和新鲜性。**

### 2.6 完整认证状态机

```
                        ┌─────────────────┐
                        │  Idle (锁定)     │
                        └────────┬────────┘
                                 │ 27 01
                                 ▼
                        ┌─────────────────┐
                        │  Seed Generated  │ ← 生成 4 字节随机 seed
                        └────────┬────────┘
                                 │ 27 02 (签名)
                                 ▼
                    ┌────────────┴────────────┐
                    │                         │
               验签通过                    验签失败
                    │                         │
                    ▼                         ▼
           ┌────────────────┐        ┌────────────────┐
           │  Unlocked       │        │  fail_count++   │
           │  (安全解锁)     │        └────────┬───────┘
           └────────────────┘                  │
                                     fail_count >= 3?
                                      ┌────┴────┐
                                     Yes        No
                                      │          │
                                      ▼          ▼
                             ┌──────────────┐  回到 Seed Generated
                             │  Lockout 30s  │  (等待下次 27 01)
                             └──────────────┘
```

## 3. 安全防护措施

| 措施 | 实现 | 代码位置 |
|------|------|----------|
| 失败次数限制 | 连续 3 次失败锁定 30 秒 | `SECURITY_MAX_FAILURES=3`, `SECURITY_LOCKOUT_MS=30000` |
| 已解锁时 seed=0 | ISO 14229 规范，避免重复计算 | `if (g_security_unlocked) resp seed = 0` |
| 签名分帧传输 | 64 字节签名通过 0x03 子功能分块发送（每帧 6 字节） | `sub_func == 0x03`，约 11 帧传完 |
| Response Pending | ECDSA 验证在 M4F 上约 30~50ms，先回 NRC 0x78 | `proto_send_nrc(0x78)` |
| 请求顺序校验 | 必须先 27 01 再 27 02，否则 NRC 0x24 | `g_seed_generated` 状态检查 |

## 4. 密钥管理

### 4.1 密钥对生成

```bash
# 生成 ECDSA P-256 私钥
openssl ecparam -genkey -name prime256v1 -noout -out docs/keys/private.pem

# 提取公钥
openssl ec -in docs/keys/private.pem -pubout -out docs/keys/public.pem

# 查看公钥坐标（写入 boot_verify.c 用）
openssl ec -in docs/keys/private.pem -text -noout
```

### 4.2 密钥对匹配验证

```bash
# 用私钥签名，再用公钥验证
echo "test" > /tmp/test.bin
openssl dgst -sha256 -sign docs/keys/private.pem -out /tmp/test.sig /tmp/test.bin
openssl dgst -sha256 -verify docs/keys/public.pem -signature /tmp/test.sig /tmp/test.bin
# 输出 "Verified OK" 表示密钥对匹配
```

### 4.3 安全约束

| 约束 | 说明 |
|------|------|
| 私钥不入 MCU | `docs/keys/private.pem` 仅存在于 PC/产线侧 |
| 公钥不可更换 | 编译后固化在 Bootloader Flash，量产时不可 OTA 更换 |
| 密钥轮换 | 更换密钥需重新烧录所有 Bootloader |
| 量产密钥 | 开发密钥必须替换为正式密钥对 |

## 5. 与镜像签名校验的关系

| 对比项 | 镜像签名校验 | SecurityAccess Seed 认证 |
|--------|-------------|-------------------------|
| 使用场景 | 上电跳转 APP 前 | OTA 升级前解锁 |
| 签名对象 | 裸固件数据（整块数据） | SHA-256(seed)（4 字节随机数） |
| 签名存储 | 镜像头 signature 字段 | 运行时通过 CAN 帧传输 |
| 验证频率 | 每次上电 | 每次安全访问会话 |
| 相同点 | 都用 ECDSA P-256 + SHA-256 + 同一把密钥对 | — |
